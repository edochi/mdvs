# TODO-0210: Chunker drops raw HTML and inline code from chunk text

## Summary

`extract_plain_text` keeps only pulldown-cmark `Event::Text`, so raw HTML and
`` `inline code` `` never reach the chunk text. On the kubernetes/website docs
corpus 7,837 of 22,729 chunks (34%) end up empty: no full-text match, an
all-zero embedding, unreachable by any search mode. On every vault, terms
written in backticks are missing from the full-text index.

## Details

Found on 2026-10-20 by the backend benchmark (TODO-0209). Every empty chunk has
an all-zero embedding and every non-empty chunk has a real one, so the model is
not at fault. 7,734 of the empty chunks are under `reference/`, mostly the API
pages, whose bodies are HTML `<table>`s
(`reference/kubernetes-api/core/pod-v1.md`).

Cause: `crates/mdvs/src/index/chunk.rs`, `extract_plain_text`, matches only
`Event::Text`. It drops:

- `Event::Code` (inline code): `kubectl`, field names, flags.
- `Event::Html` / `Event::InlineHtml`: tables, `<code>`, `<em>` and other inline
  tags around real text.

To do (decide the HTML handling with the user):

- Keep inline code text.
- Extract the text content of HTML (strip tags, keep text, decode entities),
  rather than dropping it or embedding raw markup.
- Don't store or embed a chunk whose text is empty after extraction.
- Changing chunk text changes what is indexed, so existing indexes need a
  rebuild to benefit; decide whether that triggers automatically.
- Tests: a chunk of only an HTML table, a sentence with inline code, a chunk
  that ends up empty.
- Re-run the backend benchmark and the empty-chunk count on K8s.
