# TODO-0211: Semantic search on large vaults misses most of the true top results

## Summary

From 10,000 chunks mdvs builds an IVF-PQ index and queries it with LanceDB's
defaults. On the K8s docs corpus that returns 36% of the exact top-10 chunks and
46% of the exact top-10 files. Adding `refine_factor(10)` raises both to 92% for
about 1 ms more per query.

## Details

Measured on 2026-10-20 (TODO-0209 harness, K8s docs, 22,729 chunks, 5 queries
from `docs/benchmarks/run.py`), against an exact cosine scan over the same
vectors. "Files" is what mdvs shows: top 30 chunks, best chunk per file, top 10
files.

| Setting              | Chunk recall@10 | File recall@10 | Median latency |
| -------------------- | --------------- | -------------- | -------------- |
| default (nprobes 20) | 36%             | 46%            | 0.7 ms         |
| `refine_factor(5)`   | 88%             | 90%            | 1.3 ms         |
| `refine_factor(10)`  | 92%             | 92%            | 1.6 ms         |

`nprobes` of 50, 100 or 1,000 changed nothing. The loss comes from PQ's
compressed distances, which `refine_factor` corrects by re-ranking candidates
with the full vectors.
