# TODO-0201: Emptying a file's body leaves its old chunks in the index

## Summary

When a previously indexed file's body becomes empty, incremental `mdvs build`
skips the write, so the file's old chunks stay searchable with stale content.
Affects the released v0.8.5.

## Details

Found during TODO-0197 wave 7.5 review. The file's hash changes, so it lands in
`needs_embedding`; an empty body produces zero chunks, nothing is removed, and
the write planner (`WritePlan::decide` in `crates/mdvs/src/cmd/build/write.rs`,
formerly the skip rule in `write_index_step`) chooses `Skip` because there are
no new chunks and no removed files. The old chunks and the old content hash stay
in the index, so every later build reclassifies the file and skips again.

The skip rule exists for TODO-0173 Phase A: a brand-new empty-body file (Hugo
`_index.md`) must not force a write. The fix should exempt only files with no
prior rows: a changed file that previously had chunks must have its old rows
cleared even when it now produces none.

Regression test: build with `a.md` body "X" → empty the body → build → `search`
no longer returns `a.md`'s old chunk, and a further build is a no-op.
