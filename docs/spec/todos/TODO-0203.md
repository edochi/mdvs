# TODO-0203: Upgrade lancedb and tabled to clear deny.toml advisory ignores

## Summary

`deny.toml` ignores six RustSec "unmaintained" advisories, all transitive.
Upgrading `lancedb` (0.29 → 0.40) and `tabled` (0.20 → 0.22) should clear four
of them. The other two (`paste`, `number_prefix`) come in through `model2vec-rs`
→ `tokenizers` / `hf-hub` and are not cleared by any release available today.

## Details

Found while fixing the 2026-10-19 Audit failure (`rustls` RUSTSEC-2026-0346 to
0349). Dependency data checked against crates.io on 2026-10-19.

### What each upgrade clears

| Advisory          | Crate               | Path today                                              | Cleared by                                                               |
| ----------------- | ------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------ |
| RUSTSEC-2025-0141 | `bincode` 2.0.1     | lancedb 0.29 → lance-tokenizer 6 → lindera 0.44         | lancedb 0.40 (lance-tokenizer 13 → lindera 3.x drops it)                 |
| RUSTSEC-2021-0153 | `encoding` 0.2.33   | … → lindera-dictionary 0.44                             | lancedb 0.40 (lindera-dictionary 3.x drops it)                           |
| RUSTSEC-2024-0449 | `unsafe-libyaml`    | … → lindera 0.44 → serde_yaml 0.9                       | lancedb 0.40 (lindera 3.x drops serde_yaml)                              |
| RUSTSEC-2026-0173 | `proc-macro-error2` | tabled 0.20 → tabled_derive 0.11                        | tabled 0.22 (tabled_derive 0.12 drops it)                                |
| RUSTSEC-2024-0436 | `paste`             | datafusion 53, lance-bitpacking, tokenizers 0.21        | **Not cleared**: model2vec-rs 0.3.0 still uses tokenizers 0.21           |
| RUSTSEC-2025-0119 | `number_prefix`     | model2vec-rs → hf-hub 0.4 / tokenizers → indicatif 0.17 | **Not cleared**: hf-hub 0.4 and tokenizers 0.21 still use indicatif 0.17 |

### lancedb 0.29 → 0.40 (the large one)

- lancedb 0.40 pins `lance = "=13.0.0"` and `lance-index = "=13.0.0"` (we pin
  `lance-index = "=6.0.0"` for `FullTextSearchQuery`), uses `datafusion` 54 and
  `arrow` 58 (unchanged).
- Seven Lance major versions: expect API changes in the storage and search
  backend (`crates/mdvs/src/index/backend/`, `index/storage.rs`,
  `cmd/build/write.rs`). Check TODO-0169's storage-version setting and
  TODO-0173's incremental-write path (`delete`, `add`,
  `replace_schema_metadata`, `optimize`) still hold.
- Re-run the Lance bug reproductions in TODO-0199, 0200 and 0201 on the new
  version. They may be fixed upstream, changed, or still present.
- Re-run the K8s benchmark (`docs/benchmarks/`) to catch performance
  regressions.
- Check whether the on-disk `.mdvs/` dataset from 0.29 still opens. If not,
  `build` must detect it and rebuild (or require `--force`), and the changelog
  must say so.

### tabled 0.20 → 0.22

Small. Check `render.rs` / `table.rs` against the changelog.

### paste / number_prefix (investigate, may stay ignored)

`indicatif` is an optional dependency of both `hf-hub` 0.4 and `tokenizers`
0.21. Check whether `model2vec-rs` turns it on by default, and whether
`default-features = false` (or similar) removes `indicatif` → `number_prefix`
without losing anything mdvs needs. `paste` is required by `tokenizers` 0.21
itself, so it stays until upstream moves.

### Done when

- One PR per upgrade (`chore(deps): …`): tabled first (small), then lancedb.
- The cleared entries are removed from `deny.toml` (with
  `unused-ignored-advisory = "deny"`, CI enforces this).
- The remaining entries' "Revisit when" text is updated.
- Full gate green, plus the real-model lane (`-- --ignored`) and a manual
  `example_kb` init → check → build → search sweep.
