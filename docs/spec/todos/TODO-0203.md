# TODO-0203: Upgrade lancedb and tabled to clear deny.toml advisory ignores

## Summary

`deny.toml` ignored six RustSec "unmaintained" advisories, all transitive.
Upgrading `tabled` (0.20 → 0.22) and `lancedb` (0.29 → 0.37) cleared three. The
other three (`unsafe-libyaml`, `paste`, `number_prefix`) are not cleared by any
release available on 2026-10-19 and stay ignored.

## Resolution

Both upgrades landed on one branch rather than one PR each: tabled turned out to
be a manifest bump with no code change.

### Advisories

| Advisory          | Crate               | Outcome                                                                     |
| ----------------- | ------------------- | --------------------------------------------------------------------------- |
| RUSTSEC-2025-0141 | `bincode`           | Cleared: lance-tokenizer 10 → lindera 3.x drops it                          |
| RUSTSEC-2021-0153 | `encoding`          | Cleared: lindera-dictionary 3.x drops it                                    |
| RUSTSEC-2026-0173 | `proc-macro-error2` | Cleared: tabled 0.22 → tabled_derive 0.12 drops it                          |
| RUSTSEC-2024-0449 | `unsafe-libyaml`    | Still ignored: lindera 3.0.7 → serde_yaml_ng 0.10 pulls it in               |
| RUSTSEC-2024-0436 | `paste`             | Still ignored: lance-bitpacking 10 and tokenizers 0.21 (model2vec-rs 0.3.0) |
| RUSTSEC-2025-0119 | `number_prefix`     | Still ignored: hf-hub 0.4 / tokenizers 0.21 → indicatif 0.17                |

The three cleared entries are removed from `deny.toml`; the remaining reasons
name the current path and a "Revisit when" trigger. Whether turning off the
optional `indicatif` feature removes `number_prefix` was not investigated; the
ignore's reason names it as a revisit option.

### lancedb version

`lancedb = "0.37"` (resolves to 0.37.1, Lance 10.0.0) with
`lance-index = "=10.0.0"` to match lancedb's exact pin. lancedb 0.38–0.40 do not
compile without the `remote` feature: `src/job.rs` constructs `Error::Http`,
which only exists under `#[cfg(feature = "remote")]`. Enabling `remote` would
pull in an HTTP client mdvs never uses, so 0.37 is the newest usable release.
The advisory result is the same as 0.40.

No API changes were needed in `index/backend/`, `index/storage.rs` or
`cmd/build/write.rs`. The v2.2 storage-version setting (TODO-0169) means the
same in Lance 10, and the incremental write path (TODO-0173) works unchanged.

### Existing indexes

lancedb 0.29 created a `.mdvs/__manifest` namespace directory whose config keys
trip a `debug_assert!` in lance-namespace-impls 10, so debug builds panicked
opening an old index (release builds were fine). lancedb 0.37 never creates that
directory, so `LanceBackend::connect` now deletes it if present (failure only
logs a warning).

Update (2026-10-20): old indexes open and search fine, but an incremental build
eventually panics on the frontmatter data Lance 6 wrote (see TODO-0199). The
next build after upgrading therefore rebuilds the index in full and re-embeds
every file, triggered by the `mdvs.index_format` build-metadata key.

Verified by hand with the release binary:

- `example_kb` built by the installed v0.8.6: `info`, all three search modes, an
  incremental build after an edit (runs `optimize` on the old FTS index), a
  fulltext search finding the edit, and a no-op build all succeed. The
  `__manifest` directory is gone after the first command.
- The K8s docs corpus (1,669 files, 22,729 chunks, so the IVF-PQ path) built by
  v0.8.6: an incremental build and search in each mode return 10 hits.

Test `legacy_manifest_dir_is_removed_and_index_stays_usable` covers the cleanup
with a real `__manifest` from lancedb 0.29 (fixture under
`crates/mdvs/tests/fixtures/legacy-manifest/`). The deletion is unconditional:
if a future lancedb starts writing its own `__manifest`, this code would delete
it on every connect. The comment on `lancedb` in `crates/mdvs/Cargo.toml` asks
for this check on every upgrade; the test's final incremental build is a partial
backstop.

### Behaviour changes

- Full-text BM25 scores shift by about 1–3% (one rank swap on a test query): an
  upstream scoring change, accepted.
- TODO-0199's incremental-build panic is gone (Lance 10); its regression test is
  part of this change.

### Performance

The search itself is unchanged (~3 ms engine time on K8s). Process startup is
~30 ms slower because the binary grew from 208 MB to 242 MB; TODO-0206 (strip
symbols) would recover more than that. Benchmarking also showed that default
search is ~3x slower than the June report, unrelated to this upgrade: the
default model's load cost (TODO-0205) and a needless model load on every search
when a vault has empty-body files (TODO-0204). Refreshing the published numbers
is TODO-0207. The two Lance 6 workarounds in `index/backend/search.rs` are
TODO-0208.

### Verification

Full gate green: 1,060 tests, clippy, fmt, ast-grep lint, `cargo audit` (3
allowed warnings), `cargo deny check`. Real-model lane (`-- --ignored`): 12
passed. Manual `example_kb` sweep (init → check → build → search in all three
modes, `--where`, incremental build) clean.
