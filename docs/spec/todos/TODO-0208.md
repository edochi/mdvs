# TODO-0208: Re-check the Lance 6 search workarounds on Lance 10

## Summary

`crates/mdvs/src/index/backend/search.rs` carries two workarounds for
lance-encoding 6.0 panics. TODO-0203 moved mdvs to Lance 10; check whether
either panic is gone and, if so, remove the workaround.

## Details

1. **`Array(Float)` in `--where`** (TODO-0159). `float_list_child_names` finds
   `Array(Float)` fields and the translator rejects any `--where` that names
   them, because filtering on them panicked in lance-encoding 6.0. If Lance 10
   handles it, drop the rejection and let them go through the same
   `array_has(...)` rewrite as the other array types (TODO-0191).
2. **Search projection.** `run_query` selects only five columns and leaves out
   the `data` Struct and `embedding`, because the post-vector-search "take" of
   those columns panicked. The projection is worth keeping for speed either way;
   only the comment's reason may need updating.

For each: write a test that exercises the formerly-panicking path on Lance 10
(K8s-sized data for the take, since it needs the IVF-PQ path above
`VECTOR_INDEX_MIN_ROWS`), then remove or re-word the workaround to match.
