# TODO-0202: Merge and group imports with nightly rustfmt

## Summary

Make `use` blocks consistent — one `use` per crate, grouped std / external /
crate — and enforce it in CI. Clippy has no lint for this; it is a rustfmt
concern, and the two options that do it are nightly-only. Lands on
`feat/clippy-pedantic`, in the same PR as TODO-0197.

## Details

Today import style is mixed, e.g. `main.rs`:

```rust
use std::process::ExitCode;
use tracing_subscriber::EnvFilter;
use tracing_subscriber::layer::SubscriberExt;
use tracing_subscriber::util::SubscriberInitExt;
use tracing_tree::HierarchicalLayer;
use tracing_tree::time::Uptime;
```

which the target style writes as

```rust
use std::process::ExitCode;

use tracing_subscriber::{EnvFilter, layer::SubscriberExt, util::SubscriberInitExt};
use tracing_tree::{HierarchicalLayer, time::Uptime};
```

The rustfmt options are `imports_granularity = "Crate"` and
`group_imports = "StdExternalCrate"`. Both are unstable: stable rustfmt (the
pinned `1.97.1` toolchain, and CI's `cargo fmt --check`) ignores them, so a
`rustfmt.toml` alone neither formats nor enforces anything.

Measured 2026-10-05 with `rustfmt 1.8.0-nightly (2026-01-24)`: applying both
options touches 66 files (116 hunks), all import blocks.

Plan — two commits:

1. **Config and tooling** (`chore:`):
   - Add `rustfmt.toml` with the option set below.
   - Format with nightly rustfmt only; build, clippy and tests stay on the
     pinned stable toolchain. Add a `just fmt` recipe (and `just fmt-check`)
     wrapping `cargo +nightly fmt` so nobody has to remember the toolchain.
   - CI: install a nightly toolchain with the `rustfmt` component (minimal
     profile) and replace `cargo fmt --check` with the nightly check.
   - Update every place that says `cargo fmt`: `AGENTS.md` (Build & Verify),
     `.claude/skills/agent-contract/SKILL.md` (formatting rule and gate),
     `.claude/skills/code-editing/SKILL.md`, `.claude/skills/release/SKILL.md`,
     `docs/spec/release.md`.
2. **Mechanical reformat** (`style:`): run the new formatter over the workspace,
   commit only that — no other changes — so it reviews as a pure formatting
   diff. `cargo test` and clippy must stay green.

Decision (user, 2026-10-05): **pin** the nightly to a date in one place shared
by CI and the `just` recipes, and bump it deliberately; floating on latest
nightly is rejected because rustfmt changes would cause surprise reformat churn.
The date is chosen at implementation (a recent nightly whose rustfmt supports
every option below).

Decision (user, 2026-10-05) — option set, each measured alone on the tree with
nightly rustfmt:

| Option                               | Files / hunks now | Kept because                          |
| ------------------------------------ | ----------------- | ------------------------------------- |
| `imports_granularity = "Crate"`      | 66 / 116 (pair)   | the point of this TODO                |
| `group_imports = "StdExternalCrate"` | (with the above)  | the point of this TODO                |
| `reorder_impl_items = true`          | 2 / 4             | `type` / `const` before `fn` in impls |
| `format_code_in_doc_comments = true` | 0                 | guard: formats doc examples           |
| `normalize_doc_attributes = true`    | 0                 | guard: `#[doc = ".."]` → `///`        |
| `newline_style = "Unix"`             | 0                 | guard (stable)                        |

Dropped after measuring on the pinned nightly (user, 2026-10-05):
`error_on_unformatted` and `error_on_line_overflow`. An earlier count of "0
errors" was wrong (it missed rustfmt's coloured output); they report 49 errors
at ~45 sites — 43 lines over 100 columns that rustfmt can't wrap (mostly long
string literals in tests, e.g. raw-string JSON schemas in `cmd/init.rs`) and 6
blocks rustfmt leaves unformatted because a comment would be lost. Follow-up:
those sites could be reshaped (split literals, move comments) and the two
options turned on afterwards.

Dropped after the reformat landed (user, 2026-10-05): `normalize_comments`.
Instead of only turning `/* */` into `//`, it split inline argument labels
(`/* no_update */ true,` in `cmd/hook/handle.rs`) onto separate lines and turned
a multi-line trailing `//` comment in `scaffold/template.rs` into a `/* */`
block; both spots were restored.

Rejected: `wrap_comments` (44 files; breaks aligned lists / tables in comments),
`format_strings` (22 files; splits error-message literals, hurting grep),
`match_block_trailing_comma` (45 files) and `overflow_delimited_expr` (19 files)
— taste only, high churn; `use_field_init_shorthand`, `use_try_shorthand`,
`hex_literal_case`, `condense_wildcard_suffixes`, `format_macro_matchers` —
nothing to act on (clippy already covers field-init shorthand).

## Resolution

Formatting now runs on `nightly-2026-10-04` (rustfmt 1.11.0), pinned in the
`rustfmt-toolchain` file that both the `just fmt` / `just fmt-check` recipes and
the new `fmt-rust` CI job read. `rustfmt.toml` carries the kept options. Build,
clippy and tests stay on the stable toolchain from `rust-toolchain.toml`.
`AGENTS.md`, the `agent-contract`, `code-editing` and `release` skills, and
`docs/spec/release.md` now say `just fmt` / `just fmt-check` instead of
`cargo fmt`. The mechanical reformat touched 67 Rust files and nothing else;
tests, clippy and `just lint-ast` stay green, and stable `cargo fmt --check`
also passes on the reformatted tree.
