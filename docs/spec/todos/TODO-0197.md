# TODO-0197: Clean up the codebase to pass clippy pedantic

## Summary

Make the workspace pass the full `clippy::pedantic` group, enforced through
workspace lint config so CI (`-D warnings`) keeps the code there. The cleanup is
too large for one sitting, so it runs in waves: the lint config lands first with
a temporary allow block, and each wave deletes the allows it resolves.

## Decisions

- **Config lives in the workspace.** `[workspace.lints.clippy]` in the root
  `Cargo.toml` with `pedantic = { level = "warn", priority = -1 }`; each crate
  opts in via `[lints] workspace = true`. The existing
  `#![cfg_attr(not(test), warn(unwrap_used, expect_used, panic))]` in each
  `lib.rs` stays where it is — workspace lint tables can't express the
  `not(test)` gate.
- **Permanently allowed:** `missing_errors_doc`, `module_name_repetitions`,
  `similar_names`, `must_use_candidate` (most hits are internal helpers whose
  callers always use the result — `#[must_use]` there is noise).
- **Nursery is out of scope.** This TODO covers pedantic only; nursery lints may
  be added later as a separate effort. If they are, note that a lint can't be
  both `warn` and `allow` in one TOML table, so a nursery lint can't sit in a
  temporary allow block the way pedantic lints do — each one is added as
  `"warn"` only once its sites are clean. Candidates measured above; previously
  rejected: `missing_const_for_fn` (churn, little value), `option_if_let_else`
  (often less readable), `redundant_pub_crate` (fights our `pub(crate)`
  visibility style).
- **Rollout: temporary allows.** Wave 1 enables the full set with a clearly
  marked temporary `allow` block listing every lint that fires today. Each later
  wave removes its entries from that block. CI stays green throughout and blocks
  new violations of lints that are already clean.
- **Casts use fallible conversions, never suppression.** `as` never panics, it
  silently truncates or wraps — which is exactly the problem the `cast_*` lints
  flag. Replace `as` with `TryFrom` / `try_into()` and propagate the error with
  `?` (mapped into the surrounding `anyhow` context). Never `.unwrap()` /
  `.expect()` a conversion — the existing `unwrap_used` / `expect_used` gates
  apply. Where the conversion is lossless, use `From` (`u64::from(u32)`,
  `f64::from(u32)`). Where std has no fallible API (i64 → f64), use the checked
  `num::i64_to_f64_exact` and make an inexact value an error rather than
  suppressing the lint. Where the value genuinely can't fail (elapsed-time
  milliseconds), a fallible conversion that saturates is fine
  (`u64::try_from(..).unwrap_or(u64::MAX)` behind one helper).
- **Suppressions use `#[expect]`, not `#[allow]`**, always with a `reason`, so a
  suppression that stops firing gets flagged. Existing
  `#[allow(clippy::too_many_arguments)]` sites convert in the wave that
  addresses them.
- **One branch, one commit per wave.** All waves (this TODO included) land on
  `feat/clippy-pedantic`. Commit types follow the change, not the branch:
  `chore:` for config, `refactor:` / `style:` / `docs:` for cleanup, `fix:` only
  for a real bug a lint uncovers (most likely in the cast wave).

## Waves

Every wave ends with:
`cargo clippy --all-targets --features testing-mocks -- -D warnings`,
`cargo test --features testing-mocks`, `cargo fmt`, and deleting that wave's
entries from the temporary allow block.

1. **Setup.** Workspace lint table, `[lints] workspace = true` in both crates,
   permanent allows, temporary allow block covering everything that fires. No
   code changes.
2. **Auto-fixable.** `cargo clippy --fix` for `uninlined_format_args`,
   `redundant_closure_for_method_calls`, `manual_string_new`,
   `semicolon_if_nothing_returned`, `explicit_iter_loop`, `single_char_pattern`,
   `elidable_lifetime_names`, `stable_sort_primitive`, `cast_lossless`,
   `default_trait_access`. Review the diff — `--fix` output isn't always
   idiomatic.
3. **Docs.** `doc_markdown`.
4. **Control flow.** `manual_let_else`, `single_match_else`, `map_unwrap_or`,
   `match_same_arms`, `match_wildcard_for_single_variants`, `if_not_else`,
   `items_after_statements`, `enum_glob_use`, `bool_to_int_with_if`,
   `float_cmp`, `case_sensitive_file_extension_comparisons`.
5. **Casts.** `cast_possible_truncation`, `cast_possible_wrap`,
   `cast_precision_loss` — per the fallible-conversion rule above. Review each
   site; this is the wave most likely to surface real bugs.
6. **Signatures.** `needless_pass_by_value`, `unnecessary_wraps`,
   `trivially_copy_pass_by_ref`, `ref_option`, `fn_params_excessive_bools`,
   `implicit_hasher`. Signature changes ripple to callers.
7. **Function size.** `too_many_lines` (13) and the seven existing
   `too_many_arguments` allows — real refactors, file by file. Done when the
   temporary allow block is empty and deleted.

Counts per wave are a baseline; re-measure at the start of each wave since
earlier waves shift them.

## Resolution

Done on `feat/clippy-pedantic` (commits `f5f4064`..the closing commit). The
workspace passes
`cargo clippy --all-targets --features testing-mocks -- -D warnings` with the
full `clippy::pedantic` group: `[workspace.lints.clippy]` holds `pedantic` plus
the four permanent allows, and the temporary allow block is gone. No `#[allow(`
remains under `crates/` apart from one
`cfg_attr(any(test, feature = "testing-mocks"), allow(dead_code))` on
`DEFAULT_MODEL` in `cmd/build/config_mutate.rs` (only the non-mock arm reads
it). Three `#[expect]`s remain, each with a reason: `match_same_arms` on the
literal arm in `index/backend/where_translator.rs`, and `float_cmp` on two
storage round-trip tests.

What shipped beyond lint fixes, per wave:

- **Waves 1–4** (`f5f4064`, `aa1ba2a`, `7464b99`, `7b9f550`): workspace lint
  table; mechanical fixes; `clippy.toml` `doc-valid-idents` for product names;
  control-flow rewrites.
- **Wave 5, casts** (`fcbdb03`, `67a5d85`, `eed854f`, `b2dc634`): no `as`
  numeric casts remain in `crates/*/src` (one remains in an unlinted example,
  see Follow-ups), and no cast suppressions remain. `num::i64_to_f64_exact` is a
  cast-free exact conversion; narrowing conversions use `try_from` with context;
  elapsed time goes through the saturating `step::elapsed_ms`.
- **Wave 6, signatures** (`d492b63`, `e1b7c15`): `[fields]` category thresholds
  are `Option<usize>` with `DEFAULT_*` consts and accessors; `init::run` takes
  `InitOptions { force, dry_run, scan: InitScanFlags }`.
- **Wave 7, function size** (`f3a0a20`, `769fb12`, `8083b57`, `314ae4f`,
  `41298bc`, `eacae9b`, plus the closing cleanup): shared step helpers in
  `cmd/steps.rs` used by `build`, `check`, `info`, `init`, `search` and `update`
  (not yet `export-jsonschema`, see Follow-ups); `ValidationContext`;
  `SearchQuery` / `SearchOptions` / `WhereNaming`; `build_core` as a sequence of
  phases with writes planned by `WritePlan`; `main` as per-command runners
  returning `ExitCode`. The unused `verbose` parameter is gone from
  `build`/`search`/`info`/`update::run`. Each refactor was verified by
  before/after output captures of the affected commands.

Bugs found and fixed along the way (`fix:` commits):

- `acaf88c` — the edit hook ignored `.markdown` files; it now shares the
  scanner's `is_markdown_path`.
- `fcbdb03` — integers beyond 2^53 on widened `Float` fields were silently
  rounded; they are now type errors, config range bounds beyond 2^53 on `Float`
  fields are rejected, and init / update / check / build warn when they write a
  widening field whose observed integers can't widen exactly.
- `67a5d85` — range inference rounded integer bounds through f64, producing
  bounds the source files then violated.

Other user-visible changes: a threshold written explicitly at its default value
now survives config rewrites; `format_size` rounds tenths half-up; the mock
embedder's vectors changed (test builds only).

Bugs found and filed, not fixed here: [TODO-0198](TODO-0198.md) (search results
nondeterministic on score ties), [TODO-0199](TODO-0199.md) (incremental build
panics in Lance), [TODO-0200](TODO-0200.md) (frontmatter-only edits never reach
the index), [TODO-0201](TODO-0201.md) (emptying a body leaves stale chunks).

## Follow-ups (found during the cleanup, out of scope)

- `cmd/update.rs::force_categorical` builds integer categories with
  `Value::as_i64`, silently dropping u64 values above `i64::MAX`; check then
  reports `InvalidCategory` on the files the categories came from. The same drop
  happens on the init path in `discover/infer/constraints/categories.rs`, and
  `force_categorical` duplicates that file's type check, value conversion and
  sort.
- `--where` on a `Float` column lets DataFusion cast an integer literal above
  2^53 to f64 — the same silent rounding, at query time.
- `docs/spec/architecture.md` still names `cmd/check.rs::check_field_values`;
  the code lives in `cmd/check/validate.rs`.
- `build` reports a generic "model loading failed" after the loader's own error
  step, so its final message hides the real cause; `search`, using the same
  `load_model_step`, surfaces the loader error.
- `ClassifyData::retained_chunks` is only used for its length now, but every
  incremental build still reads all chunk rows (vectors included) to fill it; a
  count would do.
- `export-jsonschema` reads and validates the config inline instead of through
  `read_config_step`, so its error lacks the `mdvs init --force` hint and it
  records no ReadConfig step.
- The `dev-examples` examples are outside every lint and CI gate;
  `examples/profile_pipeline.rs` still has a truncating `u128 as u64` cast.
- `InitOptions` / `SearchOptions` are filled from clap fields by hand in
  `main.rs`; deriving `clap::Args` and flattening (as `ReinferArgs` does) would
  remove the mapping.
- Spec drift that predates this TODO: `commands/info.md` describes an
  auto-update `info` never does; `commands/check.md` and `commands/build.md` put
  auto-update before scan; `build.md` puts the config-change check after
  classify.
- Unverified lead: `json_schema::from_canonical::json_to_toml_value` turns a
  JSON bound above `i64::MAX` into a TOML float; check whether config validation
  rejects that on an `Integer` field.
